Lesson 4: System Design Basics

Learn architecture patterns, scalability concepts, and how to design large-scale systems.

Architecture Patterns

  • Monolithic — Single deployable unit (simple, fine for small apps)
  • Microservices — Independent services communicating via APIs (scalable, complex)
  • Event-Driven — Components communicate through events (decoupled, async)
  • Layered (n-tier) — Presentation, Business Logic, Data layers (organized)

Scalability Concepts

# Horizontal Scaling — add more machines
# Vertical Scaling — upgrade existing machine

# Load Balancing — distribute traffic
# Caching — store frequently accessed data
#   - Redis / Memcached for in-memory cache

# Database Sharding — split data across databases
# Database Replication — read replicas for scaling reads

# CDN — serve static content from edge locations

Caching Strategy

# Cache-Aside Pattern
def get_user(user_id):
    # Try cache first
    user = cache.get(f"user:{user_id}")
    if user:
        return user
    # Fall back to database
    user = db.query(User).filter(id=user_id).first()
    cache.set(f"user:{user_id}", user)
    return user

CAP Theorem

In a distributed system, you can have at most 2 of 3: Consistency, Availability, Partition Tolerance.

  • CP (Consistency + Partition Tolerance) — Traditional databases
  • AP (Availability + Partition Tolerance) — NoSQL like Cassandra
